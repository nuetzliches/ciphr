Repository Threat Model

Build

Der Ausgangszustand ist der Default-Build — das Artefakt, das ein Deployment tatsächlich bekommt. Nicht „alles an".

Surface Entries schaltbar

ADR-20. Jeder Eintrag ist aus, bis ein Deployment ihn benennt — mit Datum und Grund, sonst startet der Server nicht.

    Ebenen

    • ADR-20 Property 4 — die geschlossene Liste
    • blendet aus, was das Review nicht gelesen hat
    • was die Zwiebel nicht darstellen kann

    Lesart

    • gebaut, nicht schaltbar
    • Eigenschaft des Deployments, kein Code
    • schaltbar (Surface Entry)
    • nicht gebaut oder zurückgestellt
    • reviewed core — ein Band, kein Ring
    • Schnitt: ignoriert jeden Ring

    Ringe sind keine Qualitätsstufen. Jeder Ring ist eine Grenze mit einem Gate; das Label sagt, was geprüft wird. Nach außen nimmt nicht die Qualität ab, sondern die Zahl der Parteien zu.

    Navigation

    Ziehen verschiebt, Mausrad zoomt. Tab springt zwischen den Elementen, Enter öffnet eines, Esc schließt.

    Ein Element anklicken

    Jedes Ring-, Sektor- und Schnitt-Element trägt hier seinen Text: was das Gate prüft, was es nicht prüft, und welcher Record das entschieden hat.

    Was die Zwiebel nicht kann, steht unten links: root auf dem Host und die Build-Pipeline kreuzen keine Ringe, sie ignorieren sie. Eine Zwiebel ohne diese beiden Schnitte wäre Werbung.
